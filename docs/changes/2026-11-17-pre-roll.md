# Pre-roll videos before films

A film started from the beginning now asks `GET /api/v1/items/{id}/preroll`, plays the returned
clips in order, and then mounts the existing film player. This matches Android #41. The server
chooses clips and returns none for episodes or home videos. No settings or screen type was added.

The existing Spotlight Button is focused at the bottom right and says **Skip**. It advances one
clip; Back closes the entire player, including while the list is loading. The film player is not
mounted during clips, so there is no film progress, conversion, queue selection or Up Next work.
A failed clip advances. Empty, failed or malformed lists start the film. A separate three-second
deadline ignores late responses even when the TV's fetch abort is slow.

Resume skips pre-rolls. Queue/Up Next replacements skip them, while an initial queue film from the
beginning gets them once. This app currently has no Watch Together entry point; no room playback
was added or claimed tested. Android's room exclusion remains required if that feature is added.

## Logging

New warnings name only the outcome: list failed/timed out, or clip failed and playback advances.
No exception text, titles, URLs, file names or tokens are logged. There is no per-frame or progress
logging. Main was checked before work and again before the PR; this feature was absent.
